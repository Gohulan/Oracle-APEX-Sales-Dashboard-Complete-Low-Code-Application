# SalesPulse — From Zero to Hero (Oracle APEX workshop)

## What is included

- `web/index.html`: **working standalone browser demo** with 7 interactive navigation sections, charts, order search/status filtering, CSV export and illustrative sample data. Double-click to open it. No external dependencies.
- `sql/01_schema.sql`: five normalized tables and three views.
- `sql/02_sample_data.sql`: 5 categories, 8 customers, 10 products, 120 generated orders and their order items (synthetic sample data).
- `sql/03_reports.sql`: SQL sources for interactive reports and charts.
- `sql/04_dashboard_ajax.sql`: APEX AJAX callback for real KPI, category, trend and recent-order data.
- `web/apex_home_region.html`, `web/salespulse.css`, `web/salespulse.js`: files to embed the dashboard in APEX Page 1.

## Step 1 — Create workspace

Go to https://apex.oracle.com and request a free workspace (or use your existing Oracle APEX environment). The free hosted service is for learning/evaluation, not production.

## Step 2 — Create database objects

Sign in → SQL Workshop → SQL Scripts → Upload and run `01_schema.sql`, then `02_sample_data.sql`. SQL Scripts is recommended because the seed contains a PL/SQL block and `/` terminator. If using SQL Commands, execute individual DDL/DML statements and the PL/SQL block appropriately. Do NOT rerun the seed script without resetting the tables. Confirm:

```sql
SELECT COUNT(*) FROM sp_orders;
SELECT * FROM sp_order_summary FETCH FIRST 5 ROWS ONLY;
SELECT * FROM sp_sales_by_category;
```

## Step 3 — Create application

App Builder → Create → New Application → Name **SalesPulse**. Create application. Create pages:

| Page | Page title | Wizard / data source |
|---|---|---|
| 1 | Dashboard | Default Home page, then add a Static Content region |
| 2 | Orders | Interactive Report → SQL Query from `03_reports.sql` |
| 3 | Products | Interactive Report → SQL Query, optionally add Form on SP_PRODUCTS |
| 4 | Categories | Interactive Report → Table SP_CATEGORIES, optionally add Form |
| 5 | Customers | Interactive Report → Table SP_CUSTOMERS, optionally add Form |
| 6 | Sales Reports | Chart page with revenue-by-category or monthly revenue query; add top products report |
| 7 | Inventory | Interactive Report → inventory query |

**Note:** The page numbers shown above are target numbers. Set them explicitly when creating pages, or adjust the navigation to match your actual page IDs.

## Step 4 — Embed the custom dashboard in Page 1

1. App Builder → SalesPulse → Page 1 → Page Designer.
2. Create region **Static Content** in Content Body. Paste the entire contents of `web/apex_home_region.html` into its **HTML Code** source. The file contains the dashboard's HTML markup (not the outer `html/head/body` tags).
3. Go to **Shared Components → Static Application Files** and upload `web/salespulse.css` and `web/salespulse.js`.
4. In Page 1 → Page Designer → Page → CSS → **File URLs**, add `#APP_FILES#salespulse.css`.
5. In Page 1 → Page Designer → Page → JavaScript → **File URLs**, add `#APP_FILES#salespulse.js`.
6. Save and Run. You will see the dashboard in the APEX page.
7. APEX's own page navigation may still be visible alongside the custom sidebar. For a clean full-width design, select a suitable page template/layout and hide the built-in navigation for Page 1 as appropriate to your Universal Theme version. The standalone demo is intentionally self-contained.

**Important:** The custom sidebar in the supplied HTML switches dashboard sections within Page 1. The separate native APEX pages (2–7) are also created for reporting, forms, and development demonstrations. If you want the sidebar to navigate to those native pages, replace the JS `navigate(page)` handling with links generated by APEX (`apex.util.makeApplicationUrl({pageId: ...})`) and retain appropriate session-state protection. Do not hardcode session IDs.

## Step 5 — Connect Page 1 to live database data

1. Open Shared Components → Application Processes (or Page Designer → Processing → Ajax Callback, depending on APEX version).
2. Create an **Ajax Callback** process named exactly `SP_DASHBOARD_JSON`.
3. Paste only the `DECLARE ... END;` block from `sql/04_dashboard_ajax.sql`.
4. Save, run Page 1 and click **Refresh data**.
5. KPIs, revenue trend, category bars and recent orders now come from the Oracle database.

**Live-data scope:** The standalone demo and the static Page 1 have sample catalogue/customer/inventory tables and sample order data for the non-dashboard sections. The AJAX callback updates KPI cards, trend, category charts, and recent orders, plus the orders/report lists using the most recent 8 orders. For complete live CRUD across all sections, use the native APEX report/form pages described in Step 3, or add separate AJAX endpoints. This package does **not** contain an APEX application export and is not a one-click importable APEX application.

## Step 6 — Build editable forms

Create a Form on SP_PRODUCTS, SP_CUSTOMERS, SP_CATEGORIES or SP_ORDERS. APEX uses primary keys for automatic row processing. SP_ORDER_ITEMS is a child table and requires a master-detail page or separate item-entry workflow to edit order lines. In production, add appropriate authorization, validation, auditing and business rules (including inventory checks and payment processing).

## Troubleshooting

- `ORA-00955`: Table already exists. Do not rerun schema without cleanup.
- `ORA-00942`: Wrong schema or missing grants.
- AJAX fallback data appears: check application process name, PL/SQL compilation, developer console and Network tab.
- Blank chart: ensure sample data was inserted, orders are PAID and report SQL works in SQL Workshop.
- CSS not applied: verify `#APP_FILES#` URL and browser cache.
- The dashboard shows duplicate navigation: adjust Universal Theme navigation display/template for Page 1.
- Public access: Never enable No Authentication for an app exposing business records or writable pages. Use synthetic data and restrict permissions.

## Technical notes

- Uses no third-party JS libraries, CDNs, fonts or images.
- Uses native SVG line charts and CSS bars.
- All amounts are LKR example values and do not represent real sales.
- Works as a standalone demo in modern browsers; live APEX integration requires an APEX workspace and setup.
